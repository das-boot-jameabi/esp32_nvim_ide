# ESP32 Neovim IDE

محیط توسعهٔ سبک برای firmwareهای ESP32 روی ویندوز، با Neovim، clangd و PlatformIO؛ بدون نیاز به افزونهٔ Neovim.

این مخزن شامل تنظیم ویرایشگر و راهنماهای فارسی است. کد firmware و تنظیم برد هر پروژه در مخزن جداگانهٔ همان پروژه نگهداری می‌شود.

## امکانات

- تکمیل کد C/C++، نمایش خطاها، رفتن به تعریف و تغییر نام نمادها با LSP داخلی و clangd.
- ساخت، آپلود، مانیتور سریال و تولید اطلاعات کامپایل PlatformIO در ترمینال Neovim.
- میان‌برهای ویرایش، مرور فایل‌ها و مدیریت diagnostics.

## شروع

1. Neovim نسخهٔ 0.11 یا جدیدتر، clangd و PlatformIO Core را نصب کن.
2. [فایل init.lua](nvim-esp32/init.lua) را در پوشهٔ تنظیم Neovim قرار بده؛ مسیر را با `:echo stdpath('config')` پیدا کن. تنظیم قبلی را پیش از جایگزینی پشتیبان بگیر.
3. یک پروژهٔ PlatformIO را از پوشهٔ حاوی `platformio.ini` باز کن.
4. با `:PioCompdb` اطلاعات کامپایل پروژه را بساز و Neovim را دوباره باز کن.
5. با `:checkhealth vim.lsp` اتصال clangd را بررسی کن.

## جداسازی پروژه‌ها

تنظیم Neovim یک بار نصب می‌شود و برای پروژه‌های مختلف قابل استفاده است. هر پروژه باید `platformio.ini`، فایل‌های منبع و `compile_commands.json` محلی خودش را داشته باشد. فایل آخر تولیدشده و وابسته به سیستم است و معمولاً وارد Git نمی‌شود.

پیشنهاد برای چیدمان:

```text
D:/Programming/
  esp32_nvim_ide/       ← این مخزن: تنظیم و راهنماها
  esp32-blink/          ← مخزن مستقل firmware
  esp32-sensor/         ← مخزن مستقل firmware
```

پوشه‌های محلی `hello_world/`، `espidf/` و `projects/` در این مخزن ignore می‌شوند؛ محتوای آن‌ها جزو محیط توسعه نیست. برای یک پروژهٔ موجود، در ریشهٔ همان پروژه می‌توان با `git init -b main` مخزن مستقل ایجاد کرد. این کار برای همهٔ پروژه‌ها به‌صورت خودکار انجام نمی‌شود.

این تنظیم دیباگر سخت‌افزاری و breakpoint ندارد؛ تنظیم debug با GDB/OpenOCD جداگانه انجام می‌شود.
