# راهنمای استفادهٔ روزمره

## حالت‌ها و مفهوم کلیدها

| حالت | ورود | کاربرد |
|---|---|---|
| Normal | `Esc` | حرکت، ویرایش فرمانی و میان‌برها |
| Insert | `i` یا `a` از Normal | نوشتن متن |
| Visual | `v` یا `V` از Normal | انتخاب متن یا خط |
| Command-line | `:` از Normal | اجرای فرمان؛ پایان با Enter |
| Terminal | اجرای یکی از فرمان‌های Pio | فرستادن کلیدها به برنامهٔ ترمینال |

در جدول‌های این راهنما، میان‌برها در Normal اجرا می‌شوند مگر آنکه حالت دیگری ذکر شود. `Space pb` یعنی Space، سپس p، سپس b؛ کلیدها هم‌زمان فشرده نمی‌شوند. Space در این تنظیم نقش Leader را دارد.

## گردش کار پیشنهادی

1. PowerShell را در ریشهٔ پروژه باز کن و `nvim src/main.cpp` بزن.
2. کد را ویرایش کن؛ برای ذخیره `Space w` یا `:w` بزن.
3. با `Space pb` برنامه را بساز و خروجی واقعی کامپایلر را بخوان.
4. با دو بار `Esc` از ورودی ترمینال خارج شو و با `:q` پنجرهٔ خروجی تمام‌شده را ببند.
5. برد را وصل کن و با `Space pu` آپلود کن.
6. با `Space pm` خروجی سریال را ببین.
7. پیش از آپلود بعدی، مانیتور سریال را متوقف کن تا پورت آزاد شود.

تمام فرمان‌های Pio این تنظیم، پیش از اجرا با `:wall` تغییرات bufferهای قابل‌نوشتن را ذخیره می‌کنند؛ این رفتار شامل Monitor و Compdb هم هست. اگر ذخیره شکست بخورد، اجرای فرمان ادامه پیدا نمی‌کند.

## ویرایش و جابه‌جایی پایه

| کلید یا فرمان | کار |
|---|---|
| `h`، `j`، `k`، `l` | چپ، پایین، بالا، راست |
| `w` / `b` | کلمهٔ بعدی / قبلی |
| `gg` / `G` | ابتدای فایل / انتهای فایل |
| `5j` | پنج خط پایین؛ شماره‌های نسبی برای چنین حرکت‌هایی مفیدند |
| `dd` / `yy` / `p` | بریدن خط / کپی خط / چسباندن |
| `u` / `Ctrl+r` | برگشت ویرایش / انجام دوباره |
| `/counter` و Enter | جست‌وجوی متن |
| `n` / `N` | نتیجهٔ بعدی / قبلی جست‌وجو |
| `:noh` | پاک‌کردن برجسته‌سازی باقی‌ماندهٔ جست‌وجو، اگر فعال باشد |
| `Space w` یا `:w` | ذخیرهٔ فایل فعلی |
| `:q` / `:wq` | بستن پنجره / ذخیره و بستن |

## کار با فایل‌ها و پنجره‌ها

| کلید یا فرمان | کار |
|---|---|
| `Space f` | بازکردن مرورگر فایل داخلی netrw در پوشهٔ فایل فعلی |
| `:e src/main.cpp` | بازکردن یک فایل نسبت به پوشهٔ جاری |
| `:e src/` | مرور پوشهٔ src |
| `:ls` | فهرست bufferها |
| `:bnext` / `:bprevious` | buffer بعدی / قبلی |
| `:vsplit include/config.h` | بازکردن فایل در تقسیم عمودی |
| `Ctrl+w` سپس یکی از `h/j/k/l` | رفتن به پنجرهٔ مجاور |
| `:pwd` | دیدن پوشهٔ جاری Neovim |
| `Ctrl+o` / `Ctrl+i` | عقب / جلو در تاریخچهٔ پرش‌ها |

مرورگر فایل این تنظیم جست‌وجوی fuzzy ندارد. برای جست‌وجوی ساده در فایل‌های پروژه از قابلیت داخلی استفاده کن:

```vim
:vimgrep /counter/j src/**/*.cpp include/**/*.h
:copen
```

الگوها را با فایل‌های واقعی پروژه هماهنگ کن؛ نبودن فایل مطابق الگو ممکن است پیام خطا ایجاد کند. `:cnext` و `:cprevious` بین نتیجه‌ها حرکت می‌کنند. فهرست quickfix مشترک است؛ جست‌وجو می‌تواند فهرست قبلی خطاها را جایگزین کند.

## LSP و تکمیل کد

| کلید | کار |
|---|---|
| `gd` | رفتن به تعریف نماد |
| `gr` | دیدن محل‌های استفاده از نماد |
| `K` | اطلاعات و مستندات نماد زیر مکان‌نما |
| `Space rn` | درخواست تغییر نام نماد و استفاده‌های شناخته‌شدهٔ آن |
| `Space ca` | نمایش اصلاح‌های پیشنهادی در محل فعلی، در صورت وجود |
| `Space e` | پنجرهٔ جزئیات diagnostic محل مکان‌نما |
| `Space q` | قراردادن diagnostics در quickfix |
| `Ctrl+Space` در Insert | درخواست دستی تکمیل کد |
| `Ctrl+n` / `Ctrl+p` در منوی تکمیل | پیشنهاد بعدی / قبلی |
| `Ctrl+y` در منوی تکمیل | پذیرفتن پیشنهاد انتخاب‌شده |
| `Ctrl+e` در منوی تکمیل | بستن منو بدون پذیرش |

این میان‌برهای LSP زمانی به buffer اضافه می‌شوند که یک LSP به آن متصل شود. خودکاربودن تکمیل به triggerهای پشتیبانی‌شدهٔ سرور وابسته است؛ بازنشدن منو بعد از هر حرف الزاماً مشکل نیست.

برای مرتب‌سازی کد، در صورت پشتیبانی سرور، می‌توانی دستی اجرا کنی:

```vim
:lua vim.lsp.buf.format({ async = true })
```

تنظیم فعلی format-on-save، snippet engine یا افزونهٔ قالب‌بندی جداگانه ندارد.

## ساخت، آپلود و سریال

| فرمان | میان‌بر | فرمان PlatformIO |
|---|---|---|
| `:PioBuild` | `Space pb` | `pio run` |
| `:PioUpload` | `Space pu` | `pio run -t upload` |
| `:PioMonitor` | `Space pm` | `pio device monitor` |
| `:PioCompdb` | ندارد | `pio run -t compiledb` |

این فرمان‌ها آرگومان نمی‌پذیرند. برای گزینه‌ای مثل انتخاب محیط یا پورت، فرمان مستقیم را در PowerShell اجرا کن:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" device list
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -e esp32doit-devkit-v1 -t upload --upload-port COM5
```

`COM5` و نام محیط `esp32doit-devkit-v1` مثال‌اند؛ پورت واقعی را از فهرست و نام محیط را از `platformio.ini` انتخاب کن. برای تنظیم پایدار، می‌توان `upload_port`، `monitor_port` و `monitor_speed` را در بخش محیطِ `platformio.ini` تعیین کرد.

ترمینال خروجی در یک پنجرهٔ افقی باز می‌شود. دو بار `Esc` فقط از حالت ورودی ترمینال خارج می‌کند و فرایند را متوقف نمی‌کند؛ با `i` دوباره به ورودی برگرد. برای متوقف‌کردن مانیتور، در حالت Terminal از `Ctrl+C` و راهنمای خروجی خود Monitor استفاده کن. پنجرهٔ فرایند فعال را صرفاً برای خروج از حالت Terminal به‌اجبار نبند.

ساخت و آپلود به ترتیب انجام شوند؛ این تنظیم مدیریت صف یا جلوگیری از اجرای هم‌زمان چند فرمان را ندارد. پیام موفقیت یا شکست را از خروجی PlatformIO بخوان؛ خروجی build خودکار به diagnostics یا quickfix تبدیل نمی‌شود.

## محدودهٔ امکانات

این تنظیم برای ویرایش، تحلیل کد، ساخت، آپلود و سریال است. دیباگ سخت‌افزاری، breakpoint و گام‌به‌گام‌کردن اجرا نیاز به تنظیم جداگانهٔ probe، OpenOCD/GDB و یک رابط دیباگر دارد. فعال‌بودن clangd به معنی فعال‌بودن دیباگر نیست.
